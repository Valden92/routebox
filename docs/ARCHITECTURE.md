# Архитектура и применение конфигурации

Технический справочник для разработчиков и агентов. Запуск и обычное использование
описаны в [README](../README.md) и [руководстве пользователя](USAGE.md).

Три пути: `direct` — обычная сеть, `work` — системный VPN NetworkManager,
`personal` — личный VPN через sing-box. Tauri обращается к Go-демону по локальному HTTP API.

## Компоненты

```
┌─────────────────┐     HTTP      ┌──────────────────┐
│  Tauri (UI)     │ ────────────► │  Go daemon       │
└─────────────────┘               │  nmcli, ping,    │
                                  │  subscriptions   │
                                  └────────┬─────────┘
                                           │
                    ┌──────────────────────┼──────────────────────┐
                    ▼                      ▼                      ▼
              Wi-Fi direct            tun0 (work)            sing-box tun100
```

## Закрытие приложения

Обычное закрытие Router BOX (крестик или команда выхода) завершает его демон,
автовыбор/пробные процессы, личный VPN и собственную маршрутизацию через `tun100`.
Независимый системный VPN и другие приложения продолжают работать.
Трея и скрытого фонового режима сейчас нет; systemd-сервис для этого не нужен.
Для следующего запуска достаточно обычного `make dev` без параметров.

Окно ждёт корректного завершения демона, чтобы тот успел убрать свои сетевые
ресурсы. UI отправляет SIGTERM только подтверждённому процессу Router BOX,
к которому подключился или который сам запустил, и ждёт его выхода. На Linux
используется pidfd (Linux 5.3+), защищающий от повторного использования PID.
UI не использует `killall` и не посылает SIGKILL демону.
Если завершение не подтверждено за 60 секунд, окно остаётся открытым с сообщением:
выполните `make stop` и повторите закрытие. Ошибка не маскируется выходом в фон.

Демон сохраняет единственное владение маршрутизатором через
`/run/user/<uid>/routebox-daemon.lock`, независимо от `--data`, `--listen` и XDG.
Второй демон завершается с кодом 73 до записи токена/настроек и доступа к маршрутам.
Файл блокировки не удаляется: ядро снимает блокировку при выходе процесса.
Файл на диске сам по себе не означает, что демон работает.

`make stop` также корректно завершает только подтверждённый собственный демон.
Лог запуска через make — `bin/daemon-boot.log`, при запуске из UI —
`~/.config/vpn-router/daemon-boot.log` (с учётом `XDG_CONFIG_HOME`).
Аварийная очистка после принудительного завершения остаётся отдельной явной
командой `make recover-network`. Трей, автозапуск и выбранный пользователем
фоновый режим отложены до отдельной задачи.

## Применение конфигурации и восстановление

Перед остановкой маршрутизатора кандидат проходит проверку схемы/coexist и
`sing-box check`. Когда прежний процесс работает, его конфиг сохраняется рядом
в `sing-box.json.previous-working` с правами 0600. Копия содержит параметры
подключения, как и основной `sing-box.json`; не включайте её в открытые отчёты.

После запуска проверяются ответ HTTP 200 локального Clash API и сохранение
живого процесса. Это проверка запуска маршрутизатора, а не доступности сайтов
через выбранного провайдера. Если запуск или проверка готовности не удались,
новый процесс останавливается, прежний файл восстанавливается атомарно, затем
запускается и проверяется предыдущая версия. Отмена HTTP-запроса не отменяет
восстановление. В ответе остаётся ошибка применения с результатом отката;
ошибка восстановления сообщается явно. Автоматического цикла повторов нет.

Если прежде работающего процесса не было, возвращается прежнее состояние файла
без неожиданного запуска старой конфигурации. Сохранённые настройки остаются
желаемыми: откат восстанавливает рабочий файл и процесс, а не записи правил или
выбранного сервера в настройках. После ошибки проверьте её текст до повторного
применения. Перезапуск TUN может кратковременно прерывать трафик.

## Состояние сети при генерации конфига

Для кандидата один раз собираются статус системного VPN, интерфейсы, корпоративный
DNS, маршруты и адреса VPN-сервера. Эти же значения используются в outbound, DNS,
правилах, исключениях TUN и проверке coexist. Генератор больше не перечитывает
состояние NetworkManager между секциями конфига.

Если системный VPN активен, а его интерфейс или DNS ещё не доступны, применение
возвращает понятную ошибку до остановки рабочего процесса. Ссылка на отсутствующий
`dns-work` не создаётся. При отключённом системном VPN корпоративные DNS и маршруты
не опрашиваются. Снимок не блокирует изменения ОС: если сеть изменится после сбора,
потребуется новое применение. Приоритеты правил и поведение Hysteria2 сохранены.

## Доменные правила и DNS

DNS использует тот же порядок явных доменных правил, что и маршрутизация:
ручные правила выше автоматических, внутри одного источника более конкретные
имена выше широких масок. Для одинакового шаблона побеждает ручное правило;
при одинаковом источнике — последнее. Отключённые правила не участвуют.

`direct` выбирает `dns-direct`, `personal` — `dns-proxy`, `work` — `dns-work`.
Недоступные пути пропускаются в обеих секциях. Поэтому ручной `direct` для
`api.example.org` перекрывает автоматическую personal-маску `*.example.org`
и для трафика, и для DNS. Корпоративный DNS и правила `.ru`/`.рф` остаются
встроенными DNS-значениями после явных доменных правил. Защитные маршруты
системного VPN и обход VPN-сервера сохраняют прежний приоритет.

## Фоновое обучение маршрутов

Во вкладке «Правила» переключатель «Автоматически запоминать маршруты открываемых
сайтов» управляет `autoDetectRouting`. При выключении фоновый наблюдатель не
создаёт и не обновляет правила по соединениям sing-box или истории браузера.
Результат уже начатой фоновой проверки, завершившейся после выключения, также
не изменяет правила. Существующие правила продолжают работать; кнопка
«Проверить и запомнить» по-прежнему выполняет явную проверку по запросу пользователя.
Настройка сохраняется между запусками и не требует перезапуска маршрутизатора.
Наблюдение за состоянием системного VPN работает независимо от обучения.

В API v7 `PUT /api/settings` сохраняет отсутствующие поля; переданные списки
заменяют соответствующие списки целиком, `[]` очищает список. `null` сохраняет
прежнее значение. Для переключения обучения достаточно `{"autoDetectRouting":false}`.

Неработавшее поле `defaultPath` удалено. Старые файлы, в том числе зашифрованные,
загружаются с прежним общим маршрутом `direct`: старое значение `personal`/`work`
не включает VPN для всего трафика. Поле исчезает из файла при следующем сохранении.
Если `autoDetectRouting` отсутствует в старом файле, обучение остаётся включено;
явное `false` сохраняется. Для выбора VPN используются доменные правила,
правила приложений и защитные правила маршрутизатора.

## Состояние применения конфигурации

На вкладке «Обзор» в карточке маршрутизатора показаны последний подготовленный
кандидат, подтверждённая работающая версия и последняя успешная версия.
Блок «Диагностика конфигурации» по умолчанию свёрнут; внутри есть короткое
объяснение его назначения. Заголовок раскрывает и скрывает подробности мышью
или клавиатурой. Фоновое обновление статуса сохраняет выбранное раскрытие,
при новом запуске UI блок снова закрыт.
Версия — SHA-256 содержимого сгенерированного конфига (в UI первые 12 символов).
Успешный запуск подтверждается только после проверки готовности; во время замены
или отката работающая версия помечается как неподтверждённая.

При отказе до остановки сохраняется прежний процесс. При неудачном запуске
отдельно показаны успешный откат, ошибка восстановления или восстановление файла
без ранее работающего процесса. Сохранённые желаемые настройки не заменяются
настройками старого процесса: несовпадение показывается как неприменённые изменения.
Счётчики проверок, названия подписок и переключение фонового обучения сами по себе
не помечают маршруты как изменённые.

Диагностика также доступна через защищённый `GET /api/router/configuration`
и поле `personalVpn.configuration` в `/api/status`. Этот отдельный GET читает
состояние в памяти: он не проверяет сайты, не обращается к NM и не применяет конфиг.
В нём есть причина, время/номер попытки, версии, результат отката и безопасное
описание ошибки. Исходный вывод sing-box с возможными секретами туда не копируется.

История этого состояния ограничена текущим запуском демона. До первого
подтверждённого применения версия неизвестна; после остановки процесса предыдущая
успешная версия не выдаётся за работающую. Сравнение с сохранёнными настройками
охватывает поля, используемые генератором правил, выбор сервера и интерфейса.
Внешние изменения сети и содержимого кэша узлов проверяются при следующей генерации
кандидата; это не непрерывная аттестация ОС или доступности VPN. Чтение диагностики
не запускает повторное применение и не меняет рабочую сеть.

## Объединение изменений правил и применение без перезапуска

Запросы изменения правил, пришедшие за 150 мс, ожидают одну общую попытку
применения актуальных сохранённых настроек. Во время неё новые изменения
собираются в следующую группу; параллельных применений нет. Ответ каждого
запроса приходит после результата его группы. Отмена одного запроса не отменяет
работу для остальных, но при отмене всех ожидающих участников общая попытка
отменяется. Откат уже начатой замены по-прежнему завершается независимо от
отмены. Ошибка сообщается всем участникам группы без автоматических повторов;
сохранённые настройки остаются желаемыми, как и при обычном неудачном применении.

Добавление, изменение, удаление и фоновое обучение правил обновляют локальные
`rule-set`, которые sing-box перечитывает автоматически. Остановка процесса,
пересоздание TUN и перезапуск VPN в этом пути запрещены, включая первое новое
правило и ошибки проверки. Приоритеты ручных/автоматических правил, точных
доменов/масок, приложений и одинаковый выбор DNS/трафика сохранены.
Новые соединения используют обновлённые правила; уже открытые сохраняют свой
маршрут до естественного закрытия. Наборы подхватываются асинхронно и могут
обновиться в разные моменты; API не обещает мгновенного переключения всех наборов.

Перед публикацией новая конфигурация с наборами проверяется в отдельном каталоге.
Ошибка не запускает запасной путь с перезапуском. Если изменены параметры самого
VPN или рабочий конфиг снаружи, правила сохраняются с ошибкой применения;
переподключение остаётся явным действием пользователя. Остановленный маршрутизатор
группа правил не запускает. Для нового режима нужен обычный запуск обновлённого
демона через `make dev`; работающий процесс со старым inline-конфигом автоматически
не мигрирует при добавлении правила.

В диагностике — «Правила обновлены без перезапуска VPN» и отдельная версия
опубликованных наборов (`publishedRulesVersion`, фаза `rules_published`).
Время успешного запуска и версия основного конфига не меняются. Поскольку API
sing-box не подтверждает загрузку файла, публикация не выдаётся за подтверждённую
работающую версию: соответствие сохранённым настройкам остаётся неизвестным.
Наборы приватны (`0600`, каталог `0700`) и живут рядом с конфигом, отдельно для
каждого подготовленного запуска: подготовка и откат не затрагивают наборы старого
процесса. Снимки сохраняются, в том числе для `.previous-working`.

Повтор неизменившегося правила не переписывает наборы: `reapplied:false`,
`unchanged:true`, сообщение «Правило уже существует». Создание возвращает
`status:"created"`, изменение — `updated`, повтор — `unchanged`.
Порядок сетевых префиксов из ОС и DNS стабилизирован; доменные и прикладные
приоритеты не переставляются. Смена сервера, режима VPN и явное ручное
переприменение полного конфига остаются операциями с перезапуском и откатом.

При запрошенном запуске/применении неизвестная версия, остановленный процесс,
отличающийся файл или неподтверждённая готовность не считаются no-op: действует
обычное безопасное применение полного конфига с откатом при ошибке. Это не
используется как запасной путь при публикации правил.
Явный `POST /api/personal-vpn/reapply` остаётся принудительным, чтобы можно было
перезапустить маршрутизатор для восстановления связи даже с тем же конфигом.

## Автовыбор сервера

Кнопка на карточке подписки запускает перебор узлов по списку сайтов:
сначала по весу (по убыванию), затем по пингу. Используется пробный sing-box без TUN;
прогресс N/Total, веса успех +1 / провал −1
  — до первого подходящего сервера, иначе до конца списка. Общего таймаута и скрытого
  лимита узлов нет; на каждый сайт — до 12 секунд. Явный `maxNodes` в API ограничивает
  только запрошенный пользователем перебор. Одновременно выполняется один подбор;
  результат доступен 30 минут после завершения, активное задание не истекает.
  Закрытие окна подбора (крестик, Escape или замена другим окном) останавливает
  пробный процесс; следующий подбор ждёт окончания остановки. Если выбранный
  сервер уже применяется, отмена отклоняется до завершения применения.

## Пакетная очистка доменных правил

`POST /api/rules/clear` принимает `source` (`auto` / `manual`) и список подтверждённых
`ids`. Нужна обычная авторизация локального API и разблокированные настройки.
`manual` включает прежние правила без источника и импортированные. Правила приложений
не затрагиваются. Новые ID сохраняются; если подтверждённое правило сменило источник,
возвращается `409 rules_changed` без частичного удаления.

Очистка сохраняется одной атомарной операцией Store.Update и один раз проходит
через публикацию локальных rule-set. Запасной перезапуск VPN не используется.
Повтор уже выполненного запроса возвращает `deleted: 0` и не публикует правила повторно.
Ошибка записи сохраняет прежние настройки; `reapply_failed` означает, что удаление
сохранено, но публикация не удалась. UI различает эти исходы и обновляет список.

## Группировка правил по доменам

`GET /api/rules` добавляет вычисляемое поле `domainGroup`: основной домен
по встроенной Public Suffix List и IDNA. Учитываются суффиксы вроде `co.uk`
и частные суффиксы (например `github.io`). Для IP и имён без выделяемого
основного домена сохраняется само имя. Вычисление локально, без DNS/HTTP.
Поле существует только в ответе API, не записывается в настройки и не участвует
в маршрутизации, приоритетах, DNS, ключе конфигурации или публикации rule-set.

UI группирует правила отдельно внутри каждой секции и маршрута. Счётчики,
фильтры, изменение и удаление работают с исходными правилами. Раскрытие доменов
хранится отдельно для каждой секции/маршрута. При фильтрации совпадения временно
раскрываются, после сброса возвращается сохранённое состояние. Старый API без
`domainGroup` отображается по точному хосту, без угадывания публичных суффиксов.
Связи с сайтами-источниками по решению пользователя не собираются.
