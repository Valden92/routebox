# Разработка без остановки рабочего Router BOX

Папка, из которой уже запущено приложение, остаётся рабочей копией текущей версии.
Все следующие правки и сборки выполняются в отдельном checkout. Это важно и для
Vite: изменение `desktop/src` в рабочей папке может обновить уже открытый UI через HMR.

## Подготовка

После сохранения изменений workflow в коммите выполнить из рабочей папки:

```bash
make dev-prepare
```

По умолчанию создаётся `.tmp/development/`: независимый локальный Git clone
закоммиченного HEAD с той же фичевой веткой и тем же удалённым `origin`.
Это отдельный репозиторий, поэтому коммиты и переключение веток в нём не обновляют
файлы папки с работающим приложением. Создавать новую ветку для самой подготовки
не нужно. Следующие доработки продолжаются в текущей фичевой ветке dev-копии.
Новую ветку от `main` отводить при начале работы из `main` либо по прямому
поручению пользователя; каждая новая задача сама по себе не требует новой ветки.

Не переносятся рабочие настройки из `~/.config/vpn-router/`, бинарники, PID-файлы
и индекс GitNexus. Если локальные Node-зависимости соответствуют клонированным
`package.json`/`package-lock.json`, они копируются отдельно без установки и Vite-кэшей.
Зависимости с абсолютными или выходящими за каталог символическими ссылками не копируются.
Иначе зависимости нужно установить только в `dev-checkout/desktop`.
Незакоммиченные правки исходной папки не копируются. Существующий целевой каталог
не перезаписывается; для другой папки можно указать `make dev-prepare DEV_ROOT=/path/to/dev`.

Пути записываются только в локальные Git-настройки:

- В рабочей копии: `vpnrouter.developmentRoot`.
- В dev-копии: `vpnrouter.development=true` и `vpnrouter.runtimeRoot`.

Эти настройки, `.tmp/`, зависимости и результаты сборок не публикуются в Git.
Скрипт и общие инструкции входят в репозиторий и доступны на другой машине.

## Разработка и автоматические проверки

Из dev-копии можно выполнять:

```bash
make build
make check-fmt
make lint
make test
```

`make build` пишет только в `bin/` и sidecar-каталог dev-копии. Коммиты и push
выполняются из неё по обычному workflow; рабочую копию при этом не синхронизировать.
Индекс GitNexus для анализа новых исходников создавать локально в dev-копии,
а не считать индекс рабочего checkout индексом другой версии кода.

В dev-копии Makefile по умолчанию блокирует запуск/остановку демона, UI и настройку
хоста, включая `make` без цели, `make dev`, `make desktop`, `make stop`, `make sync`
и `make recover-network`. Отдельные исходники не изолируют сеть: оба процесса всё
ещё работают на одном хосте и имеют общие VPN-интерфейсы, порты и настройки пользователя.

## Ручная проверка новой версии

Пользователь сам выбирает момент проверки и переключения версии. Агент не запускает
новый демон или Tauri, не заменяет рабочие бинарники и не выполняет reconnect/reapply.
Контейнеры и VM в этом workflow не используются.

Если пользователь решил вручную выполнить заблокированную Make-цель, требуется
явный флаг, например `ALLOW_HOST_NETWORK=1 make dev`. Это сознательный запуск
с доступом к общей сети: он может остановить текущий экземпляр. Флаг не создаёт
изоляцию и не нужен для сборки/unit-тестов. Прямые `npm run tauri dev`, запуск
бинарника или shell-скрипта обходят Make-защиту и тоже оставлены для ручной проверки.

Сам push новую версию не запускает и файлы рабочей копии не заменяет. Перенос
проверенной версии в рабочую папку и её запуск — отдельное действие пользователя.

## Установка зависимостей

`make sync` проверяет и при необходимости устанавливает:

- системные пакеты Tauri (`apt`, `sudo` если чего-то не хватает)
- **sing-box** в `~/.local/bin`
- **настройка хоста** (`setcap` на sing-box + drop-in NetworkManager для TUN, один `sudo` если ещё не сделано)
- Go (в `~/.local/go`, если `go` нет в PATH)
- Rust/cargo (через `rustup`, если нет)
- `go mod download`, `npm install`, `cargo fetch`

## Команды проверок

- `make check-fmt` — проверка gofmt, Prettier и rustfmt.
- `make lint` — golangci-lint и ESLint; `make lint-tools` устанавливает инструменты.
- `make test` — Go, UI и тесты служебных скриптов.
- `make lint-rust` — clippy; рецепт может создать отсутствующий sidecar в dev-копии.
- `make fmt` — автоформатирование.
- `make hooks` — подключить pre-commit; `make precommit` — запустить его проверки вручную.

CI выполняет Lint, Format и Test; Tauri проверяется отдельным `lint-rust.yml`.
