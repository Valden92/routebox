# Router BOX

Разработка при работающем VPN: [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md).
Команда `make dev-prepare` создаёт отдельный локальный checkout; рабочий экземпляр
не перезапускается. Не путать её с `make dev`, который перезапускает демон.

Десктопное приложение для Linux с трёхуровневой маршрутизацией:

| Путь | Назначение |
|------|------------|
| **direct** | Обычный интернет (Wi‑Fi), без VPN |
| **work** | Системный VPN (NetworkManager, профиль `PTsecurity` → `tun0`) — только из ОС |
| **personal** | Личный VPN: подписка (VLESS / Hysteria2 / SS) или файл **`.ovpn`** (OpenVPN через sing-box ≥ 1.14) |

## Возможности

- Статус интернета, системного VPN (только просмотр) и личного VPN
- Локальный маршрутизатор (`tun100`): пока приложение запущено, трафик идёт через правила
- Режимы **обычный** и **совместно с системным VPN** (coexist: изоляция `tun0`, outbound `work`, DNS)
- Автопереключение режима при появлении/пропадании системного VPN
- Автообучение доменов по живому трафику и истории браузера (приоритет: обычная сеть → системный VPN → личный)
- Правила доменов: авто и ручные, поиск, смена пути, вкл/выкл
- Вкладка приложений: скан процессов с сетью
- Системный VPN включается в NetworkManager (MFA в системе), приложение им не управляет
- Несколько подписок (одна активная): явная кнопка «Сделать активной», бейджи Выбрана / Не выбрана; выбор сервера тоже активирует подписку
- Импорт **OpenVPN** из `.ovpn` (только встроенные сертификаты; sing-box **1.14.0-beta**, pin в `make sync`)
- Метаданные URL-подписки: квота / срок (`Subscription-Userinfo`), `Profile-Title` / Announce на карточке
- Импорт **Clash / Mihomo** YAML в поле «Текст» или файлом `.yaml` (автодетект `proxies`; vless / ss / hysteria2)
- Импорт из **QR**: картинка с диска или из буфера (Ctrl+V), без камеры
- Тип подписки на карточке (URL / Share / OpenVPN / Clash / текст), даты добавления и обновления
- Список серверов, TCP‑пинг через основной интерфейс (при включённом личном VPN — ICMP), сортировка (имя / пинг / часто выбираемые)
- Сохранение выбранного сервера; при одном узле — автовыбор; при refresh — перепривязка или сброс, если узел исчез
- **Автовыбор сервера** по списку сайтов (кнопка на карточке): перебор узлов (вес ↓, затем пинг), пробный sing-box без TUN; прогресс N/Total; веса успех +1 / провал −1
  — до первого подходящего сервера, иначе до конца списка. Общего таймаута и скрытого
  лимита узлов нет; на каждый сайт — до 12 секунд. Явный `maxNodes` в API ограничивает
  только запрошенный пользователем перебор. Одновременно выполняется один подбор;
  результат доступен 30 минут после завершения, активное задание не истекает.
  Закрытие окна подбора (крестик, Escape или замена другим окном) останавливает
  пробный процесс; следующий подбор ждёт окончания остановки. Если выбранный
  сервер уже применяется, отмена отклоняется до завершения применения.
- TLS ClientHello fragment по умолчанию (анти-DPI, аналог tlshello в мобильных клиентах)
- Проверка доступности сайта по каждому пути
- Шифрование конфига паролем (API `/api/lock`, `/api/unlock`)

## Требования

Пользователь/ОС до `make sync` (проверяется автоматически):

- Linux с **NetworkManager** (служба активна, есть `nmcli`)
- **systemd-resolved** (`resolvectl`) — DNS в режиме coexist
- **polkit** — иначе личный VPN будет запрашивать системную аутентификацию
- **iproute2** (`ip`)
- **Node.js 20+** в PATH (`node` / `npm`) — sync его не ставит
- возможность **sudo** (первый sync: apt + setcap/polkit/NM)

Проверка без установки: `make check-prereqs`.

Остальное (Go, Rust, Tauri libs, sing-box, настройка хоста) ставит `make sync`.

## Быстрый старт

```bash
make sync      # зависимости + настройка TUN/NM (sudo при первом запуске)
make dev       # демон + UI
```

Первый раз удобнее: `make dev-full` (= `sync` + `dev`).

Остановка демона: `make stop`.  
Конфиг: `~/.config/vpn-router/`, API: `http://127.0.0.1:47891`

Личный VPN включается в UI **без пароля** — права выдаются при `make sync`.  
Пароль системы может понадобиться только в терминале во время `sync` (apt и настройка хоста).

Чтобы сбросить системную настройку хоста и настроить заново:

```bash
make reset-host       # убрать polkit/NM/setcap, подписки сохранить
# make reset-host-wipe  # ещё и ~/.config/vpn-router → *.bak.…
make sync && make dev
```

### Маршрутизатор и личный VPN (sing-box / TUN)

Пока приложение запущено, маршрутизатор держит `tun100` и применяет правила.  
Кнопка личного VPN включает/выключает outbound `proxy`, а не весь маршрутизатор.

Если в UI «включён», но статус «Выключен» — перезапустите демон (`make stop && make dev`) и смотрите лог: `~/.config/vpn-router/sing-box.log`.  
Если карточка просит `make sync` — выполните его в каталоге проекта (или `make configure-host` для повторной настройки).

**Если пропал интернет** после работы с личным VPN / маршрутизатором (sing-box упал, маршруты остались):

```bash
make recover-network
# или: make stop   (гасит демон и sing-box)
```

При аварийном завершении sing-box маршруты могут «залипнуть» — лучше останавливать через UI или `make stop`, а не убивать процесс насильно.

### Что делает `make sync`

Проверяет и при необходимости ставит (уже установленное не трогает лишний раз):

- системные пакеты Tauri (`apt`, `sudo` если чего-то не хватает)
- **sing-box** в `~/.local/bin`
- **настройка хоста** (`setcap` на sing-box + drop-in NetworkManager для TUN, один `sudo` если ещё не сделано)
- Go (в `~/.local/go`, если `go` нет в PATH)
- Rust/cargo (через `rustup`, если нет)
- `go mod download`, `npm install`, `cargo fetch`

## Безопасность

Подписки и URI хранятся локально в `~/.config/vpn-router/subscriptions/`.  
Для шифрования настроек: `POST /api/lock` с `{"passphrase":"..."}`.

После включения шифрования обычные изменения настроек также записываются
зашифрованными в `settings.json.enc`. Текущий сеанс остаётся разблокированным.
После перезапуска без пароля демон ожидает `POST /api/unlock` с тем же JSON:
до успешной разблокировки доступны только `GET /api/health`, `GET /api/version`
и `POST /api/unlock`, остальные операции возвращают `423 config_locked`.
Маршрутизатор и фоновые задачи до разблокировки не запускаются.
Пароль можно передать при запуске через существующий параметр `--unlock`;
отдельной формы ввода пароля в UI пока нет. Ошибка пароля или формата файла
не заменяет сохранённые настройки значениями по умолчанию.


### Доступ к локальному API (версия 6)

- Демон слушает только loopback. `GET /api/health` и `GET /api/version` остаются
  доступными для проверки запуска; остальные операции требуют Bearer-токен.
- Секрет генерируется заново при запуске и сохраняется атомарно в `.api-token`
  с правами 0600 в стандартном каталоге приложения (`$XDG_CONFIG_HOME/vpn-router`
  либо `~/.config/vpn-router`). Он не входит в JSON настроек и не выдаётся по HTTP.
- Tauri получает токен через команду IPC без аргументов; UI держит его только
  в памяти. Для запуска достаточно прежнего `make dev`, дополнительных параметров нет.
  Простой предпросмотр Vite в браузере доступа к защищённому API не получает.
- Сервер проверяет реальный loopback peer, Host и точный Origin. Разрешены адреса
  dev UI на localhost/127.0.0.1:1420 и стандартные локальные Origin Tauri
  ([справочник Tauri](https://v2.tauri.app/reference/config/)); произвольные страницы,
  `Origin: null`, другие порты и DNS rebinding отклоняются до обработчиков.
- После перезапуска демона UI заново читает токен. Повторяется только запрос,
  отклонённый защитным слоем с `401 api_auth_required`; ошибки применения,
  неверный пароль и сетевые ошибки не повторяют операции записи автоматически.
- При зашифрованных настройках токен не заменяет пароль: авторизованный клиент
  получает `423 config_locked` до `/api/unlock`.

Не помещать токен в URL, аргументы команд, логи, Git или диагностический экспорт.
Защита не является изоляцией от программ того же пользователя,
которые уже имеют доступ к его файлам.

### Безопасная загрузка URL-подписок

Добавление, ручное/фоновое обновление и загрузка отсутствующего кэша используют
один защищённый загрузчик. Разрешены публичные HTTP(S)-адреса; loopback, LAN,
link-local, CGNAT и служебные диапазоны отклоняются, включая IPv4-mapped IPv6.
Проверяются все DNS-ответы и каждый redirect; соединение открывается с проверенным
IP без повторного DNS-разрешения, а HTTPS сохраняет проверку сертификата имени сервера.
Список служебных диапазонов основан на реестрах
[IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry/) и
[IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry/).
Для IPv6 разрешены обычные global-unicast адреса и well-known NAT64 `64:ff9b::/96`
с публичным IPv4 внутри; другие переходные/служебные диапазоны запрещены консервативно.

- До 5 перенаправлений; переход HTTPS → HTTP запрещён. Basic-авторизация исходного
  URL сохраняется только для исходного origin. Referer с секретным URL не отправляется.
- Загрузка ограничена 30 секундами, заголовки — 64 КиБ, распакованное тело — 8 МиБ.
  Превышение размера возвращает ошибку вместо сохранения обрезанной подписки.
- Переменные `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` не используются этим загрузчиком.
- При отказе загрузки сохранённая подписка, выбранный узел и кэш остаются прежними.
  Локальные подписки можно добавить импортом текста/файла; URL из LAN не загружаются.

### Сертификаты Hysteria2

`pinSHA256` в ссылках Hysteria2 означает SHA-256 всего сертификата
([формат Hysteria2](https://v2.hysteria.network/docs/developers/URI-Scheme/)).
Он отличается от SHA-256 публичного ключа (SPKI). В закреплённом sing-box 1.14
поддерживается только SPKI; поле для хеша всего сертификата появляется с 1.15
([документация TLS](https://sing-box.sagernet.org/configuration/shared/tls/)).

В текущей интеграции узлы с `pinSHA256`, `pin_sha256`, `pinnedPeerCertSha256`
или `pcs` отклоняются с явной ошибкой. Это относится и к пустым/повторяющимся
значениям, разному регистру имени и сочетанию pin с `insecure=1`.
Clash-поле `fingerprint` у Hysteria2 сохраняется в ссылке для этой же проверки.
Отказ происходит до проверки доступности сервера, включения личного VPN,
остановки маршрутизатора или записи рабочего конфига. Автовыбор пропускает
такие узлы и продолжает проверять остальные поддерживаемые серверы.

Для узлов без pin сертификат проверяется обычным TLS. Явные параметры
`insecure` / `allowInsecure` / `allow_insecure` / `skipCertVerify` сохраняют прежний
смысл только при отсутствии pin. Для подключения выберите поддерживаемый сервер;
поддержка проверки полного certificate pin требует отдельного обновления интеграции.
